title: "Env"

---

## Usage

```ts
import { z } from "zod"
import { createEnv, initRuntimeEnv } from "@dapplelight/signet-server/env"

export const env = createEnv(
  z.object({ DATABASE_URL: z.string().url(), SENTRY_DSN: z.string().url().optional() }),
  { optionalFeatures: [["SENTRY_DSN", "error reporting"]] },
)

export default {
  fetch(req: Request, bindings: Record<string, unknown>, ctx: ExecutionContext) {
    initRuntimeEnv(bindings) // first thing: Workers pass secrets here, not process.env
    return app.fetch(req, bindings, ctx)
  },
}
```

`createEnv` validates on first property access, not at import. A deploy-time module load with no secrets does not fail.

## API

| Export | What it does |
| --- | --- |
| `initRuntimeEnv(env)` | Store the bindings a Worker receives. |
| `getRuntimeEnv()` | Injected bindings merged over `process.env`; injected wins. |
| `resetRuntimeEnv()` | Clear the injected bindings (tests). |
| `createEnv(schema, options)` | A Zod-validated env object, checked on first access. |
| `CreateEnvOptions` | Options type. |

### createEnv(schema, options)

| Option | Type | Default | |
| --- | --- | --- | --- |
| `optionalFeatures` | `[key, feature][]` | none | Optional vars whose absence disables a feature. Warned once. |
| `warn` | `(message) => void` | stderr | Where warnings go. |
| `source` | `() => Record<string, string \| undefined>` | `getRuntimeEnv` | Override the source. |

An invalid env throws `Invalid environment variables:` with one line per bad path.

## Examples

### Test with a fixed source

```ts
const env = createEnv(schema, { source: () => ({ DATABASE_URL: "postgres://localhost/test" }) })
```
