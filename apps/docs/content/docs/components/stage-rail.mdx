## Usage

```tsx
import { StageRail } from "@dapplelight/signet-ui/components/stage-rail"

<StageRail aria-label="Run progress" stages={["Plan", "Build", "Ship"]} current={1} />
```

Done stages are filled, the current one is filled and pulses, later ones are empty. The pulse stops when the user prefers reduced motion. Each segment has screen-reader text such as "Verify: in progress"; the rail itself is not interactive and has no tab stop. It uses [Stepper](/docs/components/stepper)'s status rule, so the same `current` works for both.

## Customising

1. **Tokens.** The segments use `bg-primary` and `bg-bg-elevated`; change those in your theme.
2. **Props.** `stages` and `current`. The words screen readers hear (`stageDone`, `stageCurrent`, `stageUpcoming`) come from `LabelsProvider`, so an app can translate them.
3. **`className`.** Merged onto the root, for example `max-w-md`.
4. **`classNames`.** `segment` and `label` replace or extend the classes of every segment and of its screen-reader text.
5. **Own the source.** `signet add stage-rail` copies the file into your project.

## API Reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `stages` | `ReactNode[]` | `-` | One title per stage, read out by screen readers. Empty renders nothing. |
| `current` | `number` | `-` | Index of the current stage, from 0. Earlier stages are done; past the end, all are; below 0, none. |
| `aria-label` | `string` | `-` | Required. Names the rail for screen readers, like "Run progress". |
| `classNames` | `Partial<Record<"segment" \| "label", string>>` | `{}` | Classes for each segment and its screen-reader text. |
| `className` | `string` | `-` | Merged onto the root. |

Plus every native `<div>` prop except `children`.

| Label key | Default |
| --- | --- |
| `stageDone` | `"done"` |
| `stageCurrent` | `"in progress"` |
| `stageUpcoming` | `"not started"` |
