### lib: offline outbox, sync conflict rules, IndexedDB storage

- `@dapplelight/signet-lib/offline`: `createOutbox<T>({ storage })` saves work done offline and `flush(send)` sends it on reconnect, keeping failures. Runs on any `StorageAdapter`. Where `navigator.locks` exists, tabs and the service worker sharing a key take turns, so an item is sent once per flush; `send` should still be safe to repeat for the same `id`.
- `@dapplelight/signet-lib/sync`: hybrid logical clock (`tick`, `receive`, `compareHlc`) and `apply(row, change, { guarded })`: per-field last-write-wins, guarded fields (amounts, dates) keep every edit on the row and `conflictOf(row, field)` gives the same open `Conflict` (`shown` plus `others`) in any arrival order. A person's pick is a `set` with `resolve: true`. Retries, however late, change nothing. Edit-after-delete is flagged (`deletedButEdited`). Tested over 2000 random two-device sessions and every order of three.
- `indexedDbStorage()` in `/storage`: larger than localStorage and reachable from a service worker. Adds its store to an existing database, and writes resolve only once the transaction commits (a full disk rejects). No new dependency.
